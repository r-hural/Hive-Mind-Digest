19. Best practices for Claude Code - Claude Code Docs

Claude Code Docs · 2026-10-20 · open

The source is Anthropic's 'Best practices for Claude Code' guide, which argues that the context window is the central constraint: it holds the whole conversation, file reads and command output, and performance degrades as it fills. Its recommended responses are to give Claude a verification step that produces a pass or fail signal (through a prompt, a /goal condition, or a deterministic Stop hook), to separate exploration, planning, implementation and commit using plan mode, and to keep context lean through /clear, /compact, /rewind, subagents for research, and fresh sessions after repeated failed corrections. The guide also covers configuration and scaling. CLAUDE.md should stay short and include only instructions Claude would otherwise get wrong, with hooks used where guaranteed behaviour is needed because CLAUDE.md is advisory. Permissions can be reduced through allowlists, sandboxing, and auto mode, which from v2.1.283 is the default starting mode for interactive terminal and VS Code sessions. CLI tools such as gh are presented as the most context-efficient way to reach external services. For automation, the guide describes claude -p with JSON or stream-json output, worktree-based parallel sessions, /batch fan-out across 5 to 30 subagents, and adversarial review by a fresh subagent that sees only the diff and criteria. The guide repeatedly frames its advice as heuristics rather than rules. It names common failure patterns, such as the kitchen-sink session, over-correction, an over-specified CLAUDE.md, trust without verification, and unscoped investigation, and asks readers to develop judgement about when to plan, when to explore, and when to clear context.

Key claims

  • Claude's context window holds the entire conversation, including every message, every file Claude reads, and every command output, and LLM performance degrades as it fills. ¶ 5
  • Give Claude a check that returns a pass or fail signal it can read, so Claude can do the work, run the check, and iterate until the check passes. ¶ 10
  • Use plan mode to separate exploration from execution, because letting Claude jump straight to coding can produce code that solves the wrong problem. ¶ 24
  • For each line in CLAUDE.md, ask whether removing it would cause Claude to make mistakes; if not, cut it, because bloated CLAUDE.md files cause Claude to ignore actual instructions. ¶ 47
  • With Claude Code v2.1.283 or later, auto mode is the built-in starting permission mode for interactive terminal and VS Code sessions; on earlier versions it is the starting mode only on Pro, Max, and Team plans. ¶ 53
  • CLI tools are the most context-efficient way to interact with external services, and without the gh CLI Claude can still use the GitHub API, but unauthenticated requests often hit rate limits. ¶ 61
  • Hooks are deterministic and guarantee the action happens, whereas CLAUDE.md instructions are advisory. ¶ 67
  • If Claude has been corrected more than twice on the same issue in one session, run /clear and start fresh with a better prompt, because a clean session with a better prompt almost always outperforms a long session with accumulated corrections. ¶ 98
  • Run /batch to have Claude split a large change across 5 to 30 subagents, each working in its own worktree. ¶ 136
  • A reviewer running in a fresh subagent context sees only the diff and the criteria given to it, not the reasoning that produced the change, so it evaluates the result on its own terms. ¶ 148
