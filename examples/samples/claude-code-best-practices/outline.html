TL;DR

  • Claude Code is a pure agentic loop with powerful terminal tools. It does no indexing and uses agentic search (glob, grep, find). It keeps no built-in memory beyond CLAUDE.md, and code stays local and is not used to train generative models.
  • CLAUDE.md is the main way context persists across sessions. It is created with /init or the # shortcut, and lives at project, user and subdirectory levels. Docs advise keeping it under 200 lines (as of 2026-10-20 and 2026-10-22), because long files cost more and get followed less. Rules that must never be broken belong in deterministic hooks, not in instructions.
  • Context is the key resource to manage. Use /clear between unrelated tasks, /compact when continuing a feature, /context to inspect usage, and sub-agents or CLI tools to limit load. After two failed corrections, rewind or clear and re-prompt. Per a source of 2026-10-12, switching models mid-chat discards the prompt cache and the cache goes cold after about an hour on a subscription.
  • Per sources of 2026-10-10 and 2026-10-22, plan mode is no longer considered necessary with newer models; describe the task, guardrails and what done looks like instead. Giving Claude a pass/fail check to verify its own work is repeatedly recommended (one source says it improves quality 2 to 3x). In a 2026-10-22 test, only two of nine popular skill packs beat a dummy file, and Anthropic has been cutting its own system prompt.
  • Costs and permissions have changed over time. As of 2025-02-25 it was a limited research preview billed via API credits. As of 2025-12-16 Opus 4.5 was available on the Pro plan, with Max at $100 or $200. As of 2026-10-20, auto mode is the built-in starting permission mode in Claude Code v2.1.283 or later. More agents are not always better: sources warn that sub-agents can multiply cost on small jobs, while a hosted multi-agent run found 66 of 70 hidden bugs against 14 to 27 for a single agent.

1. What Claude Code Is and How It Works

1.1 Core nature: a pure agentic loop

  • Claude Code is described as a very pure agent: some instructions and powerful tools, with the model run in a loop until it decides it is done. The tools are those a person skilled at a terminal would use to create and edit. [Claude Code best practices | Code w/…]
  • Claude Code has no built-in memory and only lightweight prompt instructions. A CLAUDE.md file in the working directory is placed into the prompt at startup as important developer instructions, which is how state is shared across sessions and team members. [Claude Code best practices | Code w/…, Context Management in Claude Code]
  • Claude Code knows how to use git without any git instructions in the system prompt, because the model can use git when told to. It can be asked to look through git history to explain, for example, why a function has 15 arguments. [Mastering Claude Code in 30 minutes]
  • The prompt 'commit push' makes Claude Code write a commit, push it to a newly created branch, and open a GitHub pull request without further explanation. [Mastering Claude Code in 30 minutes, Claude Code best practices | Code w/…]
  • Claude Code is fully multimodal. Images can be dragged in, pasted, or referenced by file path. [Mastering Claude Code in 30 minutes]

1.2 Search without indexing

  • Claude Code does not index or embed the codebase. It explores it with agentic search using tools like glob, grep and find, reading the results and searching further, as someone new to a codebase would. [Claude Code best practices | Code w/…]
  • Because there is no indexing, there is no setup or waiting: users download it, start it and use it right away. [Mastering Claude Code in 30 minutes]
  • Claude Code keeps no remote database of the code and does not upload it. The code stays local, and Anthropic does not train generative models on it. [Mastering Claude Code in 30 minutes]
  • Codebase Q&A is the recommended starting point above everything else. At Anthropic, technical onboarding reportedly fell from about two or three weeks to about two or three days. [Mastering Claude Code in 30 minutes]

1.3 Interface choices

3. CLAUDE.md and Persistent Memory Fundamentals

3.1 What CLAUDE.md is and why it matters

  • CLAUDE.md is a markdown file added to the project root that Claude Code reads automatically at the start of every session, and its contents are appended to the user's own prompt. [The CLAUDE.md file]
  • Without a CLAUDE.md, Claude Code starts fresh each session. It has to re-explore the codebase, work out the dependencies and already-implemented features, and sometimes makes assumptions, which makes it harder to steer. [The CLAUDE.md file]
  • Once CLAUDE.md exists, Claude uses it as context and guidance in active sessions, whether answering questions about the project or changing code. [Claude Code Tutorial #2 - CLAUDE.md…]
  • The difference between a frustrating and a productive Claude Code session comes down to context, and CLAUDE.md is how that context is provided. A suggested starting order is the stack, then preferences, then commands, building up from there. [The CLAUDE.md file]

3.2 Creating memory with /init

  • Running /init makes Claude scan the entire codebase, including folder structure, how the application starts and state management. It summarizes what it finds into a structured, human-readable CLAUDE.md in the project root. [Claude Code Tutorial #2 - CLAUDE.md…, The CLAUDE.md file]
  • For a brand-new project with virtually no setup files or code, the generated CLAUDE.md will have little in it. The user can edit it manually to outline planned structure, tools, packages or frameworks, code style preferences and an application summary, then update it as the project grows. [Claude Code Tutorial #2 - CLAUDE.md…]

3.3 Adding memories with the # shortcut

  • Typing a pound/hash sign followed by an instruction makes Claude Code remember it, and the instruction is incorporated into CLAUDE.md automatically. [Mastering Claude Code in 30 minutes, Claude Code Tutorial #2 - CLAUDE.md…, Edmund Yong]
  • When the hash is typed, the interface indicates the text will be memorized. In one example, the instruction to always add a header link when making new page components was placed in CLAUDE.md. [Claude Code Tutorial #2 - CLAUDE.md…]
  • Memories added with the hash key can be scoped locally to the project or globally across all Claude sessions. They are saved to CLAUDE.md, so they can be edited or removed later. [Edmund Yong]
  • When Claude has to be corrected, for example to use server actions instead of API routes, the user can explicitly ask Claude to save the correction to memory so it applies whenever the project is revisited. [The CLAUDE.md file]
  • Documentation in the project can be referenced from within Claude Code by using the @ symbol with the file path. [The CLAUDE.md file]

3.4 Hierarchy and scope of memory files

  • Memory files form a hierarchy. The project-level CLAUDE.md lives in the project root. A user-level CLAUDE.md lives in the user's configuration folder, applies across all of that user's projects, and suits personal preferences such as how code comments are written. [The CLAUDE.md file]
  • The project memory file is meant to be tracked by version control and pushed to the remote repository, so other developers get the same guidance. It should therefore contain project-specific information such as folder structure and naming conventions. [Claude Code Tutorial #2 - CLAUDE.md…]
  • As of 2025-08-22, the Claude Code docs said local memory was being deprecated in favor of importing untracked files within the project-level memory to provide personal context. [Claude Code Tutorial #2 - CLAUDE.md…]
  • By default Claude reads only the CLAUDE.md in the current working directory when started. CLAUDE.md files in child subdirectories are not read in by default, to avoid blowing up context in a monorepo opened at the top. Claude is encouraged to read relevant child-directory ones it discovers while searching. A CLAUDE.md can also be set in the home directory. [Claude Code best practices | Code w/…]
  • /clear wipes the conversation except CLAUDE.md, so the memory file persists across a context reset. [Claude Code best practices | Code w/…]

3.5 Keeping CLAUDE.md current and compact

  • CLAUDE.md should be kept updated when the file structure, packages or other outlined details change. Otherwise Claude Code may not pick up the changes and could go off in a completely different direction. [Claude Code Tutorial #2 - CLAUDE.md…]
  • One recommendation is to start a project without a CLAUDE.md to see where the model needs constant course-correction. This keeps the file compact and limited to necessary information. [The CLAUDE.md file]

4. Designing Lean, Effective CLAUDE.md Files

4.1 Length and instruction budget

  • CLAUDE.md should be kept as small as possible: under 300 lines and ideally shorter in one view, and under 200 lines in Anthropic's docs because longer files cost more and are followed less. [camelCase, How the Top 1% Use Claude Code…, Jay E | RoboNuggets, Claude Code Docs, 5 Claude Myths Even “Pros” Fall For]
  • Anthropic's docs say a longer CLAUDE.md makes Claude ignore rules, because important rules get lost in the noise; the file also loads on every message and so costs usage every turn. [5 Claude Myths Even “Pros” Fall For, Jay E | RoboNuggets, Claude Code Docs]
  • The most powerful models such as Claude Opus 4.5 can follow roughly 150 to 200 instructions with reasonable consistency, and smaller models significantly fewer. Claude Code's system prompt already uses about 50 of them. [camelCase]
  • Overloading with instructions degrades the quality of responses overall and all instructions are followed worse, rather than only the instructions past the limit being dropped. [camelCase]
  • Claude Code is told in a system reminder that CLAUDE.md context may or may not be relevant and should not be responded to unless highly relevant to the task. [camelCase]
  • LLMs tend to prefer instructions at the edges of the prompt, so the most important items should go at the beginning of CLAUDE.md. [camelCase]

4.2 What to include and what to leave out

  • Every CLAUDE.md can start with three building blocks: a one-line project description. [camelCase]
  • Test each line by asking whether removing it would cause Claude to make mistakes; if not, cut it. /doctor lets Claude propose cuts for content it can derive from the codebase. [Claude Code Docs]
  • Delete anything Claude already does without being told, and keep what it cannot see in the files. [5 Claude Myths Even “Pros” Fall For]
  • Code style rules do not belong in CLAUDE.md; linters and formatters should enforce style. [camelCase]
  • CLAUDE.md instructions are advisory, whereas hooks are deterministic, use no AI tokens and guarantee the action happens. A must-never-happen rule should become a hook rather than a capitalised instruction. [Claude Code Docs, How the Top 1% Use Claude Code…]
  • Letting an AI generate CLAUDE.md (such as via init) is discouraged because the output tends to be verbose. A study found tool-written context files made agents slightly worse and about 20% more costly to run. [camelCase, 5 Claude Myths Even “Pros” Fall For]
  • Giving a reason with a rule, in one short clause, helps Claude apply it correctly instead of following it blindly. Naming exact unwanted patterns works better than a general instruction such as avoiding a generic AI look. [Jay E | RoboNuggets]
  • Anthropic found that removing a 'think carefully' line made replies start sooner with no clear drop in quality on newer models. Telling Claude to double-check its work adds cost without improving results, since the Opus 5 guide says it already checks its own work. [Jay E | RoboNuggets, How the Top 1% Use Claude Code…]

4.3 Progressive disclosure, path-scoped rules and placement

  • CLAUDE.md can act as a router to other resources; domain knowledge or workflows relevant only sometimes belong in skills, which load on demand without bloating every conversation. [Jay E | RoboNuggets, Claude Code Docs, Context Management in Claude Code]
  • References should be written as a path with a note on when to open the file (e.g. read the client brief before any client work), not as an @ import, which loads the whole file into every session. [How the Top 1% Use Claude Code…]
  • Any reference file over 100 lines should get a contents list at the top, because only the first 100 lines are previewed when a file is reached indirectly. [How the Top 1% Use Claude Code…]
  • A rules file that begins with a path specification (e.g. spec.ts for tests) is read only when Claude works on matching files, so its instructions do not otherwise fill the context. [camelCase]
  • Claude automatically searches for CLAUDE.md in every parent directory, even outside the project. [camelCase]
  • Claude also reads CLAUDE.local.md for personal project-specific instructions; it should be added to .gitignore so it is not shared. [camelCase]

4.4 Pruning and ablation

  • Anthropic deletes most of Claude Code's system prompt whenever a new model ships and adds lines back one at a time, calling this ablation because newer models run better with less instruction. When the Claude 5 models came out it cut over 80% of the system prompt, reporting no measurable loss on its coding tests. [AI Edge, 5 Claude Myths Even “Pros” Fall For]
  • Boris advises running ablation every 6 months: delete the CLAUDE.md file, see what the model does bare, and expect output to probably be better than with skills and memory. [AI Edge, 5 Claude Myths Even “Pros” Fall For]
  • A minimal setup keeps context about you, your goals, and your definition of completion. Work without anything else for a day and add a line back only if the model keeps tripping on something. [AI Edge]
  • In a test of nine popular skill packs, 450 runs on Opus 5.5 showed only two beat a dummy file of the same length, and skill context did not improve output in seven of nine scenarios. [How the Top 1% Use Claude Code…, 5 Claude Myths Even “Pros” Fall For]
  • Over-specification, telling the model step by step how to reach an output, is the most common user mistake per Boris. Newer models such as Fable do worse when micromanaged. [AI Edge]

5. Context Window and Session Management

5.1 Why the context window needs managing

  • The context window holds the entire conversation: every message, every file Claude reads, and every command output. A single debugging session or codebase exploration can consume tens of thousands of tokens, and performance degrades as it fills. When the window is getting full, Claude may start "forgetting" earlier instructions or making more mistakes. [Claude Code Docs, Context Management in Claude Code]
  • Anthropic models have a context window of 200,000 tokens. Because Claude Code is an agent that calls tools, context builds up over time and a long session can max it out. [Claude Code best practices | Code w/…]
  • Without explicit instructions, Claude must look around the codebase more and do its own thinking. This takes up much more context space than adding a sentence or two of clarity to the prompt. [Context Management in Claude Code]
  • Keeping one session running across many unrelated tasks is called the "kitchen sink session" by Anthropic. It distracts Claude, so answers get worse over time. [Jay E | RoboNuggets]

5.2 /clear, /compact and /context

  • When the context window approaches its limit it is compacted automatically: important details are summarized and unnecessary tool call results removed. This frees a lot of space but could lose details from the previous conversation. [Context Management in Claude Code]
  • /context shows how large the context is, which categories take up the most context, and a graphic of this breakdown. [Context Management in Claude Code]
  • Rule of thumb: compact when working on a specific feature and going over the context window but needing to continue, since keeping the context relevant matters. Clear when the plan is finished and a new feature will start, so the previous conversation does not bias new work. [Context Management in Claude Code]
  • /clear is recommended for resetting context between unrelated tasks, since long sessions with irrelevant context can reduce performance. [Claude Code Docs]

5.3 Persisting information and reducing context load

  • MCP servers load all their available tools into context by default, so servers unrelated to the project may be worth turning off. Skills work similarly but do not put the entire thing into context. [Context Management in Claude Code]
  • CLI tools are described as the most context-efficient way to interact with external services. [Claude Code Docs]
  • Sub-agents run in parallel with the main agent but have a completely separate context window. For tasks needing an answer without the journey, such as locating authentication endpoints, the sub-agent can return just a summary to the main agent. [Context Management in Claude Code]
  • A reviewer running in a fresh subagent context sees only the diff and the criteria it is given, not the reasoning that produced the change. [Claude Code Docs, Edmund Yong]

5.4 Handling repeated failed corrections and rewinding

  • If Claude has been corrected more than twice on the same issue in one session, the context is cluttered with failed approaches. The advice is to run /clear and start fresh with a more specific prompt incorporating what was learned, since a clean session with a better prompt almost always outperforms a long session with accumulated corrections. [Claude Code Docs, Jay E | RoboNuggets]
  • Anthropic's rule, as relayed, is that after two failed corrections the user should stop correcting and use rewind to return to the point just before things went wrong, by pressing Escape twice. [Jay E | RoboNuggets]
  • Pressing Escape stops Claude mid-task so the user can interject or redirect, for example when the to-do list looks like it is on the wrong path. Pressing Escape twice lets the user jump back in the conversation. Ctrl+C pressed twice exits the program entirely rather than stopping the task. [Claude Code best practices | Code w/…, Steve (Builder.io)]

5.5 Prompt caching and session hygiene

  • On the 5.5 models, the prompt cache brings the cost of rereading the conversation on each new prompt to about 5% of the normal token amount, but that reread still counts toward usage limits. [Jay E | RoboNuggets]
  • Switching models mid-chat discards the prompt cache. An Anthropic engineer is cited as saying that 100,000 tokens into an Opus chat, switching to Haiku for an easy question costs more than letting Opus answer. [Jay E | RoboNuggets]
  • On the newest models (all 5.5 models plus Fable 5.1), changing effort mid-chat does not wipe the cache. Anthropic describes this as still in beta, so it should be checked on one's own setup. [Jay E | RoboNuggets]
  • On a subscription, the prompt cache goes cold after about an hour, so the first message back from a break is reread at full price. In one example of a conversation about 400,000 words long, continuing warm cost 15 cents versus almost $12 cold. [Jay E | RoboNuggets]
  • Claude Code deletes local session history after 30 days by default. This can be extended by setting the cleanup period days value in the settings file, for example to 365. [Jay E | RoboNuggets]

6. Planning, Prompting and Verification Workflows

6.1 Briefing Claude: plan first versus task briefs

  • Asking Claude to search, find the cause of a bug and propose a plan before fixing it lets the user read and verify the approach before any changes are made. [Claude Code best practices | Code w/…]
  • The official docs recommend using plan mode to separate exploration from execution, since jumping straight to coding can produce code that solves the wrong problem. [Claude Code Docs, How the Top 1% Use Claude Code…, 5 Claude Myths Even “Pros” Fall For]
  • Boris said in January that most of his sessions started in plan mode, but about two weeks before the video (October 2026) he said on Hacker News that plan mode is no longer useful. [How the Top 1% Use Claude Code…]
  • Instead of plan mode, the approach is to describe the task, its guardrails and what done looks like, let the model work out the plan, and check what it did afterwards. [How the Top 1% Use Claude Code…]
  • One recommendation is to skip plan mode but put a four-part brief in the first message. [5 Claude Myths Even “Pros” Fall For]
  • Prompting does not require advanced frameworks; being clear and upfront about what you want to build is enough. A prompt that cannot clearly instruct the AI suggests the author does not know what they want. [Alex Finn, Edmund Yong]
  • The first response from Claude is usually not good, so the default is to push back and iterate. When unsure what context helps, asking Claude to ask the user questions (a 'context interview') gives much better results. [Futurepedia]

6.2 Verification loops and tests

  • Giving Claude a check that returns a pass or fail it can read (test suite, build exit code, linter, output-diff script, or screenshot compared to a design) lets it do the work, run the check, and iterate until it passes; without one, the user becomes the verification loop. [Claude Code Docs, How the Top 1% Use Claude Code…]
  • Giving Claude a way to check its work lets it iterate; with a web UI mock, two or three iterations often yield an almost perfect result. [Mastering Claude Code in 30 minutes, How the Top 1% Use Claude Code…]
  • Boris said giving Claude a way to verify its work will 2 to 3x the quality of the final result. [How the Top 1% Use Claude Code…]
  • The Claude Code team's unit test coverage is abnormally high, which the speaker attributes to Claude Code making tests easy to add. [Claude Code best practices | Code w/…]

6.3 Goals and autonomous loops

  • In /goal, after every turn a separate small model such as Haiku checks whether the goal is met; the judge runs no commands and reads no files, seeing only the chat and Claude's output, so the goal must be explicit enough to be checked from that. [How the Top 1% Use Claude Code…]
  • A good goal has one end state, says how to prove it, says what must not change, and includes a turn limit. [How the Top 1% Use Claude Code…]
  • Because newer models are good at verification and can correct their own work, truly autonomous loops are practical. [AI Edge]
  • Co-work takes a goal with a defined end point, makes a plan and checklist, works through it step by step, and often delegates sub-agents to separate tasks. [Futurepedia]

6.4 Keeping standing instructions lean

  • For each CLAUDE.md line, ask whether removing it would cause Claude to make mistakes; if not, cut it, since bloated files cause Claude to ignore actual instructions. [Claude Code Docs]
  • Claude 4 follows CLAUDE.md instructions better than earlier models, so moving to new models is a good time to review what to keep. [Claude Code best practices | Code w/…]

7. Model, Effort and Cost Choices

7.1 Model selection: Opus, Sonnet and Haiku

  • As of 2026-08-16, one author recommends Sonnet as the daily driver on the Pro plan, switching to Opus for harder problems needing more reasoning. On the Max plan he sticks with Opus most of the time, especially in code or co-work, but prefers Sonnet for certain creative tasks. [Futurepedia]
  • The same author basically never uses Haiku, because the step up in response quality from Sonnet, which is still fairly fast, is always worth it to him. He also hardly ever uses Fable anymore because Opus 5 is strong and Fable is far more token-intensive for not much extra. [Futurepedia]
  • Using Haiku for sub-agents is not clearly cheaper. On Terminal Bench, Haiku 5.5 scores 39% versus 71% for Sonnet 5.5, so it gets more wrong and each wrong answer goes back to the main model to be fixed. [5 Claude Myths Even “Pros” Fall For]

7.2 Effort levels

  • Anthropic says max effort can show diminishing returns and is prone to overthinking, so setting effort to maximum is not recommended for many users. [Jay E | RoboNuggets]
  • One author's guidance as of 2026-08-16: medium effort is great for most daily tasks, high is usually for coding and analysis, and extra high is for agentic sessions or multi-step coding tasks. Extra high on tasks that do not need it takes way longer, does not improve the result, may be worse, and over-complicates things. [Futurepedia]
  • As of 2026-10-10, Opus 5.5 has a recommended effort level of medium, and Anthropic says medium matches or beats Opus 5 on high for coding and knowledge work. [How the Top 1% Use Claude Code…, Jay E | RoboNuggets]

7.3 Subscription versus API pricing

  • As of 2025-02-25, Cursor was a $20-a-month subscription, and the speaker said that for heavy use it could be better value than using the Claude API directly. [Anthropic Claude Code with Sonnet 3.7…]
  • As of 2025-07-11, Claude Code supports the standard pricing plans, and the author calls the $100-a-month Max plan an absolute steal because a human engineer costs orders of magnitude more per hour. [Steve (Builder.io)]
  • As of 2026-08-16, Claude has a generous free plan that is good for testing. A paid plan is recommended for most people because it brings much more usage, reasoning models, and access to co-work and code. [Futurepedia]

7.4 Usage limits and token-saving habits

  • Hooks are deterministic scripts that use no AI tokens and guarantee a result. [How the Top 1% Use Claude Code…]
  • Asking for three independent versions and having the agent grade each against the goal can help for anything that matters. [Jay E | RoboNuggets]

7.5 Cost of agents and extra tooling

  • The Opus 5 guide says it hands work to sub-agents more readily than any earlier model, which on small jobs multiplies cost and time. [How the Top 1% Use Claude Code…]
  • A Codex engineer said in September that running more than two agents at once almost always burns tokens for no gain in quality. In a test with 70 hidden bugs, one agent found 14 to 27 while Anthropic's hosted multi-agent run (up to a thousand agents in one job) found 66 of 70. [5 Claude Myths Even “Pros” Fall For]
  • Using /goal runs a separate small model such as Haiku after each turn to check whether the goal is met, and a good goal includes a turn limit to stop it running indefinitely. [How the Top 1% Use Claude Code…]

8. Permissions, Safety and Guardrails

8.1 Default permission behaviour and approval prompts

  • As of 2026-10-20 (Claude Code v2.1.283 or later), auto mode is the built-in starting permission mode for interactive terminal and VS Code sessions. A separate classifier model reviews most actions and blocks only what looks risky, such as scope escalation, unknown infrastructure, or hostile-content-driven actions. On earlier versions, auto mode is the starting mode only on Pro, Max, and Team plans. [Claude Code Docs]
  • In Manual mode Claude Code asks before file writes, Bash commands and MCP tools. This is safe but tedious, and after the tenth approval users tend to click through rather than review. [Claude Code Docs]

8.2 Auto-accept and skip-permissions trade-offs

  • Running with permissions skipped carries serious risk. One user reported that Claude deleted his entire C drive in that mode (he recovered most of it from backups), and at least four similar reports from Windows users have come in since September. Auto mode, where a second check reviews actions, is suggested instead. [Jay E | RoboNuggets]

8.3 Risks of unchecked automation and safety nets

  • The /security-review command sends an agent to review the app for security, which matters especially when vibe coding. [Alex Finn, Context Management in Claude Code]

9. Extending Claude Code: Slash Commands, MCP, CLI Tools, Skills and Plugins

9.1 Custom slash commands

  • Typing a slash on its own in Claude Code lists all available commands, which can be scrolled with the up and down keys. [Claude Code Tutorial #6 - Slash Commands]
  • A custom command is a markdown file placed in a commands folder inside the .claude folder, and the file name becomes the command name. Commands can be sorted into subdirectories as the library grows. [Claude Code Tutorial #6 - Slash Commands, Edmund Yong]
  • When a custom command runs, Claude Code pulls in its markdown file and uses the contents as a prompt. [Claude Code Tutorial #6 - Slash Commands]
  • The Claude session must be restarted before Claude Code picks up a newly created custom command. [Claude Code Tutorial #6 - Slash Commands]
  • One presenter had seen no official guidance on passing multiple values from the arguments variable. A method using square brackets to create variables worked well for him. [Claude Code Tutorial #6 - Slash Commands]
  • Running /batch splits a large change across 5 to 30 subagents, each working in its own worktree. [Claude Code Docs]

9.2 MCP servers versus CLI tools

  • Claude Code can be given more capability either by installing CLI tools or by attaching MCP servers. When a well-known, well-documented CLI tool exists, the recommendation is to use it rather than an MCP server. [Claude Code best practices | Code w/…]
  • Examples of MCP uses: adding 'use Context7' to a prompt makes Claude call the Context7 server to fetch the latest library documentation. The Playwright and Chrome DevTools servers let Claude debug and test front-end issues by controlling the browser and inspecting the DOM and console logs. [Edmund Yong]

9.3 Hooks, sub-agents and headless use

  • Each sub-agent gets its own context window, system prompt and tool permissions, which reduces pollution of the main context window. For tasks that need an answer without the journey, a sub-agent can return just a summary. [Edmund Yong, Context Management in Claude Code]
  • One user spent a couple of hours assigning sub-agents roles such as front-end developer, UI/UX designer or product manager and found results pretty bad compared with using Claude Code with no agent-specific instructions. [Edmund Yong]

9.4 Skills

  • One presenter reported that installing a Claude design skill with two commands and asking Claude to redesign the UI with it produced a much more professional-looking interface than the default. [Alex Finn]
  • Anthropic's skill guide says to first complete a task without a skill, note where Claude went wrong, and build the skill only from those real corrections. [How the Top 1% Use Claude Code…]

9.5 Plugins

  • As of 2025-10-27, Anthropic had recently released plugins, which bundle a user's Claude setup into a single package so that a power user's whole workflow can be cloned with a single command. [Edmund Yong]

10. Sub-agents and Multi-agent Orchestration

10.1 What sub-agents are and how they are defined

  • Sub-agents let a user build a team of specialised agents, each operating independently with its own context, expertise, MCP tools or system prompt. Workflows such as code reviews, debugging or testing can be delegated to them while the main conversation stays focused. [Claude Code NEW Sub Agents in 7 Minutes]
  • Agents are created with /agents. The user chooses whether the agent lives in the project or globally on the machine, then configures it manually or generates it with Claude. [Claude Code NEW Sub Agents in 7 Minutes]
  • Each agent's tool access can be set individually. Core functions such as listing, reading and editing files, and tools from connected MCP servers, can be turned on or off. [Claude Code NEW Sub Agents in 7 Minutes]
  • The agent description tells Claude Code when to invoke it. The system prompt can accumulate preferences over time, such as avoiding linear gradients, thick fonts or emojis. [Claude Code NEW Sub Agents in 7 Minutes]
  • Agents are markdown files, so their context is portable and can be committed to a repository. [Claude Code NEW Sub Agents in 7 Minutes]
  • Giving each agent its own specific do and don't instructions is preferred over squeezing every facet of an application's workflow into one system prompt. [Claude Code NEW Sub Agents in 7 Minutes]

10.2 What sub-agents are good for

  • Sub-agents reduce pollution of the main context window and suit offloading smaller, specific tasks. [Edmund Yong]
  • In a web-research demo, an agent searched the internet and returned five relevant AI news stories. [Claude Code NEW Sub Agents in 7 Minutes]

10.3 Coordinating multiple agents

  • Claude Code has no native multi-agent communication. The best current approach described is for agents to write shared state to a file, such as a ticket.md, which another agent reads. [Claude Code best practices | Code w/…]
  • For large migrations or analyses, /batch splits a change across 5 to 30 subagents, each working in its own worktree. Fan-out can also be driven from a script by looping over claude -p. [Claude Code Docs]
  • In a code-review fan-out workflow, Claude fans out to find bugs, and each candidate bug may get an adversarial review from three perspectives. This filters out false positives and leaves the most important bugs. [How the Claude Code team uses Claude…]
  • In a workflow the agent writes code to orchestrate sub-agents, mixing deterministic code behaviour with agentic LLM behaviour. One speaker says this improves trust, for example because a for loop will not skip items. [How the Claude Code team uses Claude…]
  • Claude can design its own harnesses, including the fan-out topology and how one agent's output feeds the next level before a final summary is returned. [How the Claude Code team uses Claude…]
  • The SDK can be used headlessly and programmatically, for example in CI/CD and GitHub, to sprinkle a coding agent anywhere. [Claude Code best practices | Code w/…]

10.4 When more agents help or waste tokens

  • Orchestration scaffolding can go stale as models improve. Many harness features cover failure modes of the current model and can be removed later. A to-do list that helped with Sonnet 3.5 was no longer needed about a year later. [How the Claude Code team uses Claude…]

Claude Tag's primary interface is a messaging tool in Slack, with a link to the full transcript. [How the Claude Code team uses Claude…]

11.4 Autonomous loops and scheduled agents
