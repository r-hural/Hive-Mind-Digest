Claude Code best practices — Research Summary

Generated: 2026-10-26 | Sources: 18 videos, 1 article, 13 channels

TL;DR

  • Claude Code is a pure agentic loop with powerful terminal tools. It does no indexing and uses agentic search (glob, grep, find). It keeps no built-in memory beyond CLAUDE.md, and code stays local and is not used to train generative models.
  • CLAUDE.md is the main way context persists across sessions. It is created with /init or the # shortcut, and lives at project, user and subdirectory levels. Docs advise keeping it under 200 lines (as of 2026-10-20 and 2026-10-22), because long files cost more and get followed less. Rules that must never be broken belong in deterministic hooks, not in instructions.
  • Context is the key resource to manage. Use /clear between unrelated tasks, /compact when continuing a feature, /context to inspect usage, and sub-agents or CLI tools to limit load. After two failed corrections, rewind or clear and re-prompt. Per a source of 2026-10-12, switching models mid-chat discards the prompt cache and the cache goes cold after about an hour on a subscription.
  • Per sources of 2026-10-10 and 2026-10-22, plan mode is no longer considered necessary with newer models; describe the task, guardrails and what done looks like instead. Giving Claude a pass/fail check to verify its own work is repeatedly recommended (one source says it improves quality 2 to 3x). In a 2026-10-22 test, only two of nine popular skill packs beat a dummy file, and Anthropic has been cutting its own system prompt.
  • Costs and permissions have changed over time. As of 2025-02-25 it was a limited research preview billed via API credits. As of 2025-12-16 Opus 4.5 was available on the Pro plan, with Max at $100 or $200. As of 2026-10-20, auto mode is the built-in starting permission mode in Claude Code v2.1.283 or later. More agents are not always better: sources warn that sub-agents can multiply cost on small jobs, while a hosted multi-agent run found 66 of 70 hidden bugs against 14 to 27 for a single agent.

5. Context Window and Session Management

5.1 Why the context window needs managing

  • The context window holds the entire conversation: every message, every file Claude reads, and every command output. A single debugging session or codebase exploration can consume tens of thousands of tokens, and performance degrades as it fills. When the window is getting full, Claude may start "forgetting" earlier instructions or making more mistakes. 2 sources Best practices for Claude Code - Claude Code Docs ¶ 5, Context Management in Claude Code 0:03
  • Anthropic models have a context window of 200,000 tokens. Because Claude Code is an agent that calls tools, context builds up over time and a long session can max it out. Claude Code best practices | Code w/ Claude 14:07
  • Without explicit instructions, Claude must look around the codebase more and do its own thinking. This takes up much more context space than adding a sentence or two of clarity to the prompt. Context Management in Claude Code 2:12
  • Keeping one session running across many unrelated tasks is called the "kitchen sink session" by Anthropic. It distracts Claude, so answers get worse over time. Claude 5.5 Model Mistakes you may still be making (23 Tips and Fixes) 1:31

5.2 /clear, /compact and /context

  • When the context window approaches its limit it is compacted automatically: important details are summarized and unnecessary tool call results removed. This frees a lot of space but could lose details from the previous conversation. Context Management in Claude Code 0:36
  • /context shows how large the context is, which categories take up the most context, and a graphic of this breakdown. Context Management in Claude Code 1:18
  • Rule of thumb: compact when working on a specific feature and going over the context window but needing to continue, since keeping the context relevant matters. Clear when the plan is finished and a new feature will start, so the previous conversation does not bias new work. Context Management in Claude Code 1:33
  • /clear is recommended for resetting context between unrelated tasks, since long sessions with irrelevant context can reduce performance. new Best practices for Claude Code - Claude Code Docs ¶ 98

5.3 Persisting information and reducing context load

  • MCP servers load all their available tools into context by default, so servers unrelated to the project may be worth turning off. Skills work similarly but do not put the entire thing into context. Context Management in Claude Code 2:24
  • CLI tools are described as the most context-efficient way to interact with external services. new Best practices for Claude Code - Claude Code Docs ¶ 61
  • Sub-agents run in parallel with the main agent but have a completely separate context window. For tasks needing an answer without the journey, such as locating authentication endpoints, the sub-agent can return just a summary to the main agent. Context Management in Claude Code 2:43
  • A reviewer running in a fresh subagent context sees only the diff and the criteria it is given, not the reasoning that produced the change. 2 sources Best practices for Claude Code - Claude Code Docs ¶ 148, 800+ hours of Learning Claude Code in 8 minutes (2026 tutorial / unknown tricks / newest model) 7:20

6. Planning, Prompting and Verification Workflows

6.1 Briefing Claude: plan first versus task briefs

  • Asking Claude to search, find the cause of a bug and propose a plan before fixing it lets the user read and verify the approach before any changes are made. Claude Code best practices | Code w/ Claude 15:16

  • Boris said in January that most of his sessions started in plan mode, but about two weeks before the video (October 2026) he said on Hacker News that plan mode is no longer useful. new How the Top 1% Use Claude Code Differently 0:04
  • Instead of plan mode, the approach is to describe the task, its guardrails and what done looks like, let the model work out the plan, and check what it did afterwards. new How the Top 1% Use Claude Code Differently 1:07
  • One recommendation is to skip plan mode but put a four-part brief in the first message. partly supported new 5 Claude Myths Even “Pros” Fall For 3:26

  • Giving Claude a check that returns a pass or fail it can read (test suite, build exit code, linter, output-diff script, or screenshot compared to a design) lets it do the work, run the check, and iterate until it passes; without one, the user becomes the verification loop. 2 sources new Best practices for Claude Code - Claude Code Docs ¶ 10, How the Top 1% Use Claude Code Differently 3:56

6.3 Goals and autonomous loops

  • In /goal, after every turn a separate small model such as Haiku checks whether the goal is met; the judge runs no commands and reads no files, seeing only the chat and Claude's output, so the goal must be explicit enough to be checked from that. new How the Top 1% Use Claude Code Differently 5:25

8. Permissions, Safety and Guardrails

8.1 Default permission behaviour and approval prompts

  • As of 2026-10-20 (Claude Code v2.1.283 or later), auto mode is the built-in starting permission mode for interactive terminal and VS Code sessions. A separate classifier model reviews most actions and blocks only what looks risky, such as scope escalation, unknown infrastructure, or hostile-content-driven actions. On earlier versions, auto mode is the starting mode only on Pro, Max, and Team plans. new Best practices for Claude Code - Claude Code Docs ¶ 53
  • In Manual mode Claude Code asks before file writes, Bash commands and MCP tools. This is safe but tedious, and after the tenth approval users tend to click through rather than review. new Best practices for Claude Code - Claude Code Docs ¶ 53

  • Running with permissions skipped carries serious risk. 10. Sub-agents and Multi-agent Orchestration

10.1 What sub-agents are and how they are defined

  • Sub-agents let a user build a team of specialised agents, each operating independently with its own context, expertise, MCP tools or system prompt. Workflows such as code reviews, debugging or testing can be delegated to them while the main conversation stays focused. Claude Code NEW Sub Agents in 7 Minutes 0:02
  • Agents are created with /agents. The user chooses whether the agent lives in the project or globally on the machine, then configures it manually or generates it with Claude. Claude Code NEW Sub Agents in 7 Minutes 0:37
  • Each agent's tool access can be set individually. Core functions such as listing, reading and editing files, and tools from connected MCP servers, can be turned on or off. partly supported Claude Code NEW Sub Agents in 7 Minutes 1:14
  • The agent description tells Claude Code when to invoke it. The system prompt can accumulate preferences over time, such as avoiding linear gradients, thick fonts or emojis. Claude Code NEW Sub Agents in 7 Minutes 2:31
  • Agents are markdown files, so their context is portable and can be committed to a repository. Claude Code NEW Sub Agents in 7 Minutes 5:46
  • Giving each agent its own specific do and don't instructions is preferred over squeezing every facet of an application's workflow into one system prompt. Claude Code NEW Sub Agents in 7 Minutes 5:23

10.2 What sub-agents are good for

  • Sub-agents reduce pollution of the main context window and suit offloading smaller, specific tasks. 800+ hours of Learning Claude Code in 8 minutes (2026 tutorial / unknown tricks / newest model) 4:23
  • In a web-research demo, an agent searched the internet and returned five relevant AI news stories. partly supported new Claude Code NEW Sub Agents in 7 Minutes 6:05

10.3 Coordinating multiple agents

  • Claude Code has no native multi-agent communication. The best current approach described is for agents to write shared state to a file, such as a ticket.md, which another agent reads. Claude Code best practices | Code w/ Claude 25:06
  • For large migrations or analyses, /batch splits a change across 5 to 30 subagents, each working in its own worktree. Fan-out can also be driven from a script by looping over claude -p. new Best practices for Claude Code - Claude Code Docs ¶ 136
  • In a code-review fan-out workflow, Claude fans out to find bugs, and each candidate bug may get an adversarial review from three perspectives. This filters out false positives and leaves the most important bugs. new How the Claude Code team uses Claude Code 11:25
  • In a workflow the agent writes code to orchestrate sub-agents, mixing deterministic code behaviour with agentic LLM behaviour. One speaker says this improves trust, for example because a for loop will not skip items. new How the Claude Code team uses Claude Code 13:25
  • Claude can design its own harnesses, including the fan-out topology and how one agent's output feeds the next level before a final summary is returned. new How the Claude Code team uses Claude Code 12:10
  • The SDK can be used headlessly and programmatically, for example in CI/CD and GitHub, to sprinkle a coding agent anywhere. Claude Code best practices | Code w/ Claude 8:58
