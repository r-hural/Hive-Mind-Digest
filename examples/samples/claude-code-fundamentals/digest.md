## 4. The future of agentic coding with Claude Code

Anthropic · 2025-09-02 · 20:20 · [watch](https://www.youtube.com/watch?v=iF9iV4xponk)

The speakers, Anthropic's Claude Relations lead Alex and Claude Code creator Boris, argue that coding has shifted within about a year from copy-pasting code in chat apps and autocomplete-assisted IDEs to agents that are part of the daily development loop. They attribute this to model improvements from Sonnet 3.5 to newer models such as 3.7, 4.0 and Opus 4.1, which keep working autonomously for longer, and to harness work: the system prompt, context management, tools, MCP servers, settings and permissions that wrap the model. Claude Code's extensibility has grown from the CLAUDE.md file to hooks, slash commands and subagents, and the team relies on a fast internal feedback loop and daily use, or vibes, because synthetic evals are hard to build and saturating. ## 5. How we Claude Code

Claude · 2026-05-23 · 31:43 · [watch](https://www.youtube.com/watch?v=IlqJqcl8ONE)

The workshop, given by an Anthropic Applied AI architect, argues that as models get more capable, agents can run longer on more complex tasks, so users should change how they work with Claude Code. Three ideas are central: stop over-constraining the model and let it interview you (via the ask-user-question tool) to extract requirements you may not articulate up front; replace long Markdown specs, which go unread past about 200 lines, with dense HTML specs and design directions that are easier to review visually, using screenshots for front-end feedback; and build verification into the artifact itself. Recommended settings include auto mode, the effort parameter, Opus 4.7 over Sonnet, and fast mode for spec iteration. The verification demo uses a React to-do app in which each component publishes its state to the DOM, separate from React internals, so an agent can read it directly. Schemas, fixtures, known states and invariants are tested with probes. The same checks can be run from a human dashboard, through an agent in the browser using Playwright MCP, or headlessly with 'bun verify' in CI. The speaker shows that deleting one DOM element breaks every check, which demonstrates a broken contract rather than a broken app. Verification runs can be recorded as clips and shared as evidence; the speaker says the Claude Code team records most front-end changes this way. Much of the material is presented as the speaker's recommendation rather than measured results, including the claim that HTML specs are not more token-inefficient over time.
